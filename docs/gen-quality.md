# 生成侧质量（LLM 路径）

检索评测（Recall / MRR / FinanceBench 页级命中）只说明「正确的片段有没有被捞出来」，不说明「模型拿到片段后答得怎么样」。这一页补上后者：用本地 OpenAI 兼容网关（默认 `trae-cn/deepseek-v4.1-flash`，`temperature 0.1`）跑 50 条可答题 + 10 条不可答题，测量引用遵循率、引用支撑度、答案对金标片段的覆盖，以及拒答行为。

测量日期 2026-11-28，检索为 **BM25 单路**（与 `serve.py` 同口径；`backend` 只决定构建哪个嵌入索引，不再影响排序），`top_k=5`，可答题从 `eval/qa.jsonl`（120 条）等距取 50 条。

## 结果

| 指标 | 值 |
|---|---:|
| 检索命中金标 chunk@5 | 0.720（36/50） |
| 模型作答率 | 0.960（48/50） |
| 作答里引用零编造（citations ⊆ 检索片段） | 1.000（48/48） |
| 平均引用条数 | 1.76 |
| 平均引用支撑度（答案 token 落在引用片段） | 0.896 |
| 答案 token 落在金标 chunk 的比例 | 0.669 |
| 金标 chunk 被答案覆盖的比例 | 0.117 |
| 检索命中时模型作答率 | 0.972（35/36） |
| 检索未命中时模型拒答率 | 0.071（1/14） |
| 不可答题（10 条）正确拒答率 | 1.000 |

## 怎么读这张表

1. **生成的瓶颈在检索，不在模型。** 检索命中金标的 36 题里，模型答了 35 题（0.972）；检索没命中的 14 题里模型只拒 1 题——但那些回答多是题干歧义下从片段里挑出的可追溯枚举（见第 5 条），不是「有依据」。要提升端到端表现，先投检索（评测集修正、表格解析），而不是换更大的模型。
2. **引用可追溯，但不等于答案正确。** 48 条作答的 citations 全部是本次检索提供的 chunk id（零编造）——因为提示里已给出 id 列表，模型只需复制。这证明「引用来源可核对」，但不能当准确性证据。
3. **引用支撑度 0.896**：答案的绝大多数词能在它自己引用的片段里找到，属于「有据可查」的下限证据；词级近似，不是语义级评审。
4. **「金标被答案覆盖」只有 0.117，不要当错误率读**：金标是该题来源的整段 chunk（可能上百字），而答案通常只有一句，分母天然大。该值只用于纵向比较，不用于判定对错。
5. **未命中金标仍作答的题目需要人工复核**：可能是相邻 chunk 讲同一件事（合理），也可能是拼凑（不可接受）。2026-11-27 那次运行（检索为向量候选）里 22 条未命中、12 条仍作答，次日已逐条抽查：11 条作答的数字全部能在所引片段里找到（0 条编造）；其中 6 条引的是同文档相邻片段、答案与金标事实一致，4 条是题干歧义下可追溯的枚举，1 条答成别家公司的数字，另 1 条重跑时拒答。根因见「局限」里「评测集约四成题目不可靠」一条。
6. **不可答题目 100% 拒答**：离题问句在 LLM 模式下会被「无引用即拒答」的规则挡住，这是相对抽取式路径的明确改进。

## 局限

- 样本 50 + 10 条，`hash` backend，单次运行。
- **2026-11-27 那版表测的是向量候选，不是 BM25，已不可与当前表混比。** 当时默认 `top_k=5` 下 `hybrid_search` 的 RRF 融合结果恒等于向量候选集合（每条向量候选至少 `1/(60+5)+1/(60+375)≈0.018`，高于 BM25 第 1 名的 `1/61≈0.016`），BM25 只在这 5 条内部重排；同一语料 BM25 单路 recall@5 是 0.775（见 README）。2026-11-28 起 `serve.py` 与本页的测量脚本都改为 BM25 单路，旧数字（命中 0.560、误拒 0.260）仅作对照。
- **评测集约四成题目不可靠。** 120 题里 48 题题干在金标 chunk 文本中定位不到（多为「标题前 20 字 + 相关数字是多少」的兜底题），另有至少 3 条金标与当前切分疑似错位（金标 BM25 排 #84–#115，题干短语实际出现在同文档相邻 chunk）。因此「检索命中金标」「金标覆盖」与「未命中时拒答率」都掺入了「题目本身不可答」的成分，只作量级参考。
- 问题由正文句子改写生成（答案就在原句所在 chunk），词面重合度高，指标整体偏乐观——与检索评测同一局限。
- **拒答判定在 `temperature 0.1` 下抖动明显**：同一份 25 条子集、同一检索配置，两次跑出误拒率 0.520 与 0.400。该指标需多次运行取均值才可作为结论，单次数字（如本表的 0.040）只当作量级参考。
- 引用支撑度与覆盖度都是词级近似（中文单字 + 二元组），不做语义判定；不含数值正确性、不含跨文档推理。

## 复现

需要本机有 OpenAI 兼容端点（`FINRAG_LLM_BASE_URL` / `FINRAG_LLM_MODEL` / `FINRAG_LLM_API_KEY`，见 README「接生成模型」）。

```
make gen-quality                                   # 默认 50 条可答 + 10 条不可答
python scripts/measure_gen_quality.py --limit 5    # 小样本试跑
```

脚本为 `scripts/measure_gen_quality.py`：`build_index` → 每题 BM25 单路取 top-5（与 `serve.py` 同口径）→ `build_prompt` → `chat` → `parse_model_json` → `llm_answer`，再以 `citation_support`（引用支撑度）与 token 交集（金标覆盖）统计；明细默认写 `results/gen-quality.json`（`results/` 已在 `.gitignore` 里）。
